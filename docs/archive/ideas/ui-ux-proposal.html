From “capable” to “professional”: a UI/UX proposal

Solvro already has the bones of a serious delivery tool: a strict token system, a dark-first theme, and real Kanban, Gantt, and S-curve views. What keeps it from reading as a professional project-management product is not the aesthetic. It is inconsistency and noise: the same fact is shown four different ways, low-value details compete with high-value ones, and some states leak raw data.

Recommendation: do not redesign. Keep “Technical Precision” exactly as docs/DESIGN.md defines it. Run three small phases: a consistency pass (one vocabulary, one date format, one button style), a hierarchy pass (project header, Kanban card, Overview), and a polish pass (loading states, navigation, mobile). Phase 1 alone removes most of the “unfinished” feel.

What already works — keep it

These are strengths. The proposal protects them.

Disciplined token system

Tonal surfaces and 1px borders instead of shadows. One accent colour. This is how Linear and Jira’s current UI look “serious”.

Real planning views

Gantt with baseline, dependencies, and week/month/quarter zoom. S-curve with slip. These are features that make a tool look enterprise-grade.

Data-dense tables

Tasks and Epics tables use label-caps headers, mono IDs (T-055, P-001), and dense rows. Keep this as the model for every list.

Task side panel

A property sheet (Assignee, Dates, Priority, Epic…) that opens beside the board. This is the correct pattern — it keeps the context.

Global search ⌘K

A command palette is a “pro tool” signal. Extend it to actions (see Phase 3).

Considered empty states

Utilization and Executive empty states explain the cause and the next step. Use the same pattern everywhere.

Findings

Ranked by how much each one hurts the “professional” impression. P1 = a user notices it on day one. P2 = a user notices it in week one. P3 = detail polish.

Theme A · Consistency

P1

1 · One task status has four labels — and one is a raw enum

The status IN_PROGRESS shows as “In Progress” on the Kanban column, “In progress” in the Gantt and task panel, “Active” in the project List view, and “IN_PROGRESS” on Daily Review. Risks show “OPEN”. “Active” is also the project status, so a TAM reads a task as a project state.

The Daily Review cause: <SelectValue /> renders the option’s value, not its label.

Fix: one label map per enum in lib/ (taskStatusLabel, riskStatusLabel, priorityLabel). Every chip, column, select, and export reads it. Sentence case: “To do”, “In progress”, “Done”.
pages/views/ProjectList.tsx:65 · components/kanban-v2/SolvroKanban.tsx:62 · components/daily-review/ProjectCard.tsx:261
Daily Review: raw IN_PROGRESS and OPEN in the select triggers.

P1

3 · Two button styles, two create verbs

“NEW PROJECT”, “NEW CUSTOMER”, “EDIT”, “DELETE” use uppercase tracking. “Add task”, “Add epic”, “Edit project”, “Create task” use sentence case. Some create buttons say “New”, others say “Add”.

Fix: sentence case on every button. Uppercase stays for text-label-caps micro-labels and column headers only, as DESIGN §2 already says. Verb rule: “New …” opens a create form for a top-level entity; “Add …” inserts into the current container.
pages/Projects.tsx:104 · pages/Customers.tsx:51,210,220
Customers: uppercase text buttons, and person names in a monospace font (see #15).
P1

4 · Priority has three looks

Kanban: a grey “Med” pill on every card. Task form: orange uppercase “MEDIUM”. List view: a flag icon with colour only, no text. Colour alone does not pass WCAG 1.4.1.

Fix: PriorityBadge everywhere, flag + word. Hide it when the value is the default (Medium) on dense surfaces — show only High and Urgent. PriorityBadge stays bespoke (standing decision); the change is inside the file.

Theme B · Information hierarchy

P1

5 · The project header hides the facts and promotes “Delete”

A PM opens a project to answer: who is the customer, when does it end, how far along is it, is it healthy? The header shows only “TAM maya.putri · 17 tasks”. Meanwhile Delete project is a peer button beside Edit on every tab.

Fix: a project header strip — customer, date range, progress bar, baseline slip, health. Actions: “Edit” + an overflow menu (⋯) with Baseline, Export, Delete. “Context” becomes an icon toggle. Mockup below.
Current: three equal outline buttons; Delete is one click away on every tab.
P1

6 · Kanban cards carry 6–8 signals each

Every card shows: drag grip, title, duration, ⋯ menu, epic pill, comment count (even “0”), Critical Path chip, priority, avatar. With 3 columns, that is ~50 competing marks per screen. The saturated epic pills (solid blue, orange, violet, red) are the loudest thing on the board — louder than status or overdue.

Fix: progressive disclosure. Show zero counts never. Show default priority never. Show the due date instead of a duration. Show the epic as a dot + text. Show Critical Path as an icon with a tooltip. Show the drag grip and ⋯ only on hover. Target: ≤4 marks per card.
Current To Do column: “0” comments, “Med” on 4 of 5 cards.
P2

7 · User colours bypass the chip doctrine

Epics and labels render as solid, fully-saturated fills (for example a pure blue for “Backup platform”, a red for “customer-action”). Every other chip in Solvro uses a tinted background + a light text pair (DESIGN §1). Solid blue also reads as a brand/CTA colour, which DESIGN §5 reserves for green.

Fix: keep the user’s hue, change the treatment: 8px dot + 14% tint background + on-surface text. Red stays out of the label picker so it never reads as “error”. Needs your decision — LabelChip is user-gated.
P2

8 · Overview leads with vanity numbers

“Welcome back, Admin. A high-density snapshot of your active workload.” reads as marketing copy. The four KPI cards (Total tasks 59, Completed 26…) do not ask for an action. The actionable block, “Projects needing attention”, sits below the fold. The portfolio timeline uses 64px rows with 8px bars and truncates every project name.

Fix: “My work” first — Overdue, Due this week, Waiting on customer, each a clickable count. Then “Needs attention”. Then a compact timeline (32px rows, name column fixed at 280px). Mockup below.
Current Overview at 1440×900: nothing actionable above the fold.
P2

9 · Tasks page opens on finished work

The cross-project Tasks list defaults to “sort by due, ascending, all statuses”. The first 20 rows are all Done tasks from May–September. A TAM must filter every visit.

Fix: default to open tasks, overdue first, then due date. Offer saved views: “My open”, “Overdue”, “This week”, “All”.
Tasks: every visible row is Done.

Theme C · Navigation & wayfinding

P2

10 · Nine unlabelled icons in one flat rail

The collapsed sidebar shows 9 icons with no groups and only a native browser title tooltip (1–2 s delay). Daily Review, Weekly Sync, and Tasks use similar list glyphs. A new TAM cannot learn the product from the rail.

Fix: groups — Workspace (Overview, My tasks, Projects, Customers), Rituals (Daily review, Weekly sync), Insights (Utilization, Executive), then Settings/Admin at the bottom. Styled instant tooltips with the keyboard shortcut. Badge counts on Daily review (unreviewed) and My tasks (overdue). Mockup below.
components/layout/Sidebar.tsx:72
P2

11 · The top bar says “Solvro” on 6 pages

PAGE_TITLES has 5 entries. Daily Review, Weekly Sync, Utilization, Executive, Settings, and Admin fall back to “Solvro”. Projects says “My Projects” while its H1 says “Projects”. Customer detail has no breadcrumb — it uses a separate “‹ CUSTOMERS” back link — while Project detail has one.

Fix: breadcrumbs on every page from one route map: Customers / PT Nusantara Logistik, Projects / Veeam Backup Rollout / Gantt. Remove the back link.
components/layout/TopBar.tsx:10-16, 39
P2

12 · Mobile project header collides

At 390px the project name disappears; the “Active” chip overlaps the search icon. “Edit project” and “Delete project” wrap to two lines each and take the first screen.

Fix: on <640px show only the truncated project name + status. Move all actions into the ⋯ menu. Scroll the tab row horizontally with a fade edge.
390px: breadcrumb and chip overlap the search icon.

Theme D · States & feedback

P2

13 · Blank boxes while data loads

In my first capture, the Epics tab showed only an empty bordered box; the rows appeared on a later capture. Kanban, Gantt, Services, Settings, and Help have no skeleton at all. A blank box looks like a broken page.

Fix: three shared skeletons — table rows, card grid, board columns — reused by every view. Show them after 150 ms so fast loads do not flash.
Epics tab, first capture: no skeleton, no spinner.
P3

14 · “Soon” placeholders in the product

Customer detail has tabs and cards for Topology and Organization structure marked “SOON”. A bright mint “Profile complete” banner — the most eye-catching element on the page — reports a state that needs no action.

Fix: hide unbuilt tabs until they ship. Replace the success banner with a small check next to the customer name.
Customer detail: success banner + “SOON” sections.

Theme E · Typography details

P3

15 · Monospace on names, not only on data

Person names (“Hendra Gunawan”, “Sarah Tan”) and Daily Review counters render in monospace. DESIGN §2 scopes mono to dates, IDs, and tabular numerics. Overview counters use Source Sans for the same kind of number.

Fix: names in the body font. Numbers in Source Sans with font-variant-numeric: tabular-nums. Mono only for IDs and code.
P3

16 · Too many micro sizes

Chips use 11px, the top-bar role uses ~10px, the “TODAY” marker ~9px, table text 13px, and body 15px. Five sizes below 15px make the UI feel busy.

Fix: two small sizes only — 13px (text-xs) for secondary text and 12px (text-label-caps) for labels. Chips move from 11px to 12px.

Button rule
Sentence case. No uppercase buttons.
One primary (green) button per view.
“New …” = new top-level entity. “Add …” = insert into this container.
Destructive actions live in ⋯ menus and always confirm.
Icon-only buttons have an aria-label and a tooltip.

Roadmap

Three phases, each one branch and one PR into develop. Scope stays frontend-only. No backend or schema change is needed.

PHASE 1 · CONSISTENCY

Say one thing one way

  • Label maps for status, risk, priority (#1, #4)
  • Date formatter module (#2)
  • Button casing + verbs (#3)
  • Complete PAGE_TITLES / breadcrumbs (#11)
  • Mono clean-up, chip 12px (#15, #16)

Risk: low. Touches StatusChip/PriorityBadge in-file only. Gantt tree dates touch gantt-v2/ → spine review.

PHASE 2 · HIERARCHY

Show what matters first

  • Project header strip + ⋯ menu (#5)
  • Kanban card diet (#6)
  • Label / epic colour treatment (#7) — gated
  • Overview “My work” (#8)
  • Tasks default view + saved views (#9)

Risk: medium. Kanban card is in kanban-v2/ (spine for adapter only). Needs e2e selector updates.

PHASE 3 · POLISH

Feel fast and finished

  • Shared skeletons (#13)
  • Grouped sidebar + tooltips + badges (#10)
  • Mobile project header (#12)
  • Hide “Soon” tabs, quiet success banner (#14)
  • ⌘K actions: “New task”, “Go to…”

Risk: low. Pure presentation.

Decisions I need from you

1
Label and epic colours (#7). LabelChip is user-gated. Change it to dot + tint, or keep solid fills? Recommend: dot + tint.
2
“Soon” tabs on Customer detail (#14). Hide until built, or keep as a roadmap signal? Recommend: hide.
3
Sidebar default (#10). Expanded with labels on screens ≥1280px, or keep collapsed? Recommend: expanded on ≥1280px, remember the user’s choice.
4
Kanban card date (#6). Replace the duration (“10 Days”) with the due date? Recommend: yes — duration stays in the Gantt.

Method and limits

What I did

  • Drove the local dev stack with Playwright as admin, demo seed data (6 projects, 59 tasks).
  • Captured 20 routes at 1440×900 dark, 2 in light, 3 at 390px.
  • Checked each finding against docs/DESIGN.md and the source file named in the finding.

What I did not cover

  • No user testing with TAMs — findings are expert review only.
  • iTop was not connected, so the Tickets board and Utilization data states are unseen.
  • Light mode Gantt and most mobile screens were not captured.
  • No full WCAG audit — only the colour-only priority flag (#4) was checked.
