# Optional SA + Sustained Gantt Color Legend — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> **Repo pipeline:** each task is dispatched to `solvro-implementor`, then `solvro-qa` → `solvro-reviewer` → `solvro-docs-keeper` per CLAUDE.md's Agent Roster. Tasks 2–3 activate the reviewer's design lens (they touch `frontend/`).

**Goal:** Make the Solution Architect assignment optional end-to-end, and replace the Gantt's unlabeled color segmented-control with a "Color by" dropdown whose legend is sustained in all three modes.

**Architecture:** Task 1 makes `Project.saId` nullable (migration + Zod schemas + a new `disconnect` path) behind the existing REST surface. Task 2 flips the frontend types to `sa: … | null` and lets the resulting typecheck errors enumerate every consumer, fixing each with null-safe rendering; customer-facing exports omit the SA line rather than printing a placeholder. Task 3 extracts the section-color fallback resolution into a shared `resolveSectionColors()` in `palette.ts` so the new dynamic Section legend and `geometry.ts`'s bars can never disagree, and swaps the segmented control for a token-styled native `<select>`.

**Tech Stack:** Prisma migration (PostgreSQL), Express + Zod, React + TanStack Query, Playwright e2e. No new dependencies.

**Spec:** `docs/ideas/optional-sa-and-gantt-color-legend.md`

```ts
// Single resolution point for section colors, shared by geometry.ts's
// buildRows and the toolbar legend so the two can never disagree. Sections
// whose stored color is missing or still the schema-default slate sentinel
// (#94a3b8) have never been through the color picker and get a vivid preset
// assigned deterministically by (position, id) order; explicit picks always
// win — the sentinel is excluded from SECTION_COLOR_PRESETS so a user pick
// can never collide with it.
export function resolveSectionColors(
  sections: ReadonlyArray<Pick<Section, "id" | "position" | "color">>,
): Map<number, string> {
  const sorted = [...sections].sort((a, b) => a.position - b.position || a.id - b.id);
  const map = new Map<number, string>();
  sorted.forEach((s, index) => {
    const stored = s.color?.trim();
    const isUnset = !stored || stored.toLowerCase() === DEFAULT_SECTION_COLOR.toLowerCase();
    map.set(
      s.id,
      isUnset ? SECTION_COLOR_PRESETS[index % SECTION_COLOR_PRESETS.length] : stored,
    );
  });
  return map;
}

export function legendEntries(
  mode: ColorByMode,
  sections: ReadonlyArray<Pick<Section, "id" | "name" | "position" | "color">> = [],
): Array<[string, string]> {
  if (mode === "status") {
    return [
      ["To Do", STATUS_FILL_HEX.TODO],
      ["In Progress", STATUS_FILL_HEX.IN_PROGRESS],
      ["Done", STATUS_FILL_HEX.DONE],
    ];
  }
  if (mode === "priority") {
    return [
      ["Low", PRIORITY_BORDER_HEX.LOW],
      ["Medium", PRIORITY_BORDER_HEX.MEDIUM],
      ["High", PRIORITY_BORDER_HEX.HIGH],
      ["Urgent", PRIORITY_BORDER_HEX.URGENT],
    ];
  }
  // Section mode: one entry per section in board order, resolved through the
  // same fallback cycling the bars use.
  const colors = resolveSectionColors(sections);
  return [...sections]
    .sort((a, b) => a.position - b.position || a.id - b.id)
    .map((s): [string, string] => [s.name, colors.get(s.id) ?? DEFAULT_SECTION_COLOR]);
}
```
