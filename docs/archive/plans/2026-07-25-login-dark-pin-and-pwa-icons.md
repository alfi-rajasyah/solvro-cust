# Bug-fix pair: always-dark Login + branded PWA icons

**Date:** 2026-07-25 · **Branch:** `fix/login-dark-and-pwa-icons` off up-to-date `origin/develop` (v4 migration is merged there, PR #62) · **PR target:** `develop`

## Context

Two regressions reported with screenshots:

1. **Login renders light.** `/login` shows a white page when the OS prefers light mode. `Login.tsx:99` already pins the `dark` class on its root div (DESIGN.md:292 documents this as intended), but the pin silently broke in the Tailwind v4 CSS-first migration (commit `e00ed06`).
2. **iOS home-screen icon is a dark square with a white blob.** All 4 PWA icons were generated by compositing the *on-dark* Elitery mark (off-white arc + green crescent) onto a **#3aae51 green plate** — the green crescent vanishes into the plate, leaving an unrecognizable white half-dome. The apple-touch-icon additionally has transparent, pre-rounded corners; iOS flattens alpha onto **black**, producing the dark frame in the screenshot.

User decisions (2026-07-25): icons get an **opaque #232321 charcoal plate with the full two-tone mark**; the app's first-visit default theme **stays `"system"`** (only the pins get fixed — the DESIGN.md `theme_default: dark` vs code discrepancy goes to ISSUES.md, not this fix).

## Task 1 — Restore subtree `dark` pins (Login + Sidebar rail)

### Root cause

`frontend/src/index.css:12` opens a **non-inline** `@theme` block. Non-inline `@theme` emits `--color-background: rgb(var(--background))` etc. into `:root`, and utilities compile to `var(--color-background)`. Per CSS spec, the inner `var(--background)` is substituted **at `:root`**, freezing the light value; a `dark` class on a *nested* element (Login.tsx:99, Sidebar.tsx:59) overrides the RGB triplet for its subtree but the frozen `--color-*` value wins. Whole-app flips still work because `ThemeProvider` puts `.dark` on `<html>` = `:root` itself. Pre-migration, Tailwind v3 inlined `rgb(var(--token))` into each utility, which is why the pins used to work. The comment at `index.css:8-11` claiming var-in-var resolves at the consuming element is the wrong assumption to remove.

### Change

1. **`frontend/src/index.css`**: change `@theme {` (line 12) → `@theme inline {`. Utilities then compile to the inlined value `rgb(var(--background))`, resolving at the consuming element — restores exactly the semantics `Login.tsx`/`Sidebar.tsx` already assume. Fix the stale comment at lines 8-11. (Opacity modifiers keep working — v4 wraps inline values in `color-mix`.)
2. **Compat block** — `@theme inline` stops emitting `--color-*` custom properties at `:root`, which the vendored Gantt reads **raw** (not via utilities):
   - `var(--color-primary)`: `reui/gantt/gantt-bar.tsx:275`, `gantt-view.tsx:3365,3736`, `gantt-dnd.tsx:297,370,673`
   - `var(--color-background)`: `gantt-dnd.tsx:313`
   - Already-dead today (referenced but never emitted, pre-existing): `var(--color-border)` `gantt-view.tsx:1801,2053,2117`, `var(--color-destructive)` `gantt-dnd.tsx:674`

   Add a plain `:root { ... }` compat block in `index.css` (next to the `@theme inline` shadcn bridge) re-declaring just these four: `--color-primary`, `--color-background`, `--color-border`, `--color-destructive`, mapped to the same underlying values the theme blocks use. This fixes the two dead references as a bonus and avoids editing vendored files (no new `// SOLVRO PATCH` sites). Root-level declaration is correct for these consumers: the Gantt only lives under the `<html>`-level theme flip, never inside a subtree pin.
3. **No changes** to `Login.tsx`, `Sidebar.tsx`, or `theme.tsx` — the existing pins and provider (`frontend/src/lib/theme.tsx`, `useTheme()`/`applyClass()`) are already correct once the CSS is fixed. No FOUC work needed: Login's pin is static JSX, dark from first paint.

### Risks

- Broad blast radius: every semantic-color utility recompiles. Mitigate by diffing built CSS (spot-check `.bg-background`, `.bg-surface` now inline) and running the full Playwright suite — especially `gantt-parity`, `gantt-legend`, `gantt-bar-labels`.
- Light mode must keep working everywhere except `/login` and the sidebar rail (TopBar toggle + Settings ThemeCard are real features).
