# Restructure `docs/ISSUES.md` into a triaged ledger

Status: shipped 2026-11-18, branch `docs/workflow-cleanup`. Archive path: `docs/archive/plans/issues-restructure.md`.

## Goal

Turn `docs/ISSUES.md` from a log of deferred findings, one section per phase, into a file of open issues sorted by area and severity, each with an ID that never changes. The old file is kept verbatim in `docs/archive/`. Every old entry is classified as open, merged, fixed or obsolete, and each closing verdict carries evidence that can be checked.

## Current state before the change (measured at `6dd7592`)

- The file had 2,456 lines and 54 `##` sections, most titled "<phase> — deferred findings (date)", from 2026-07-24 to 2026-11-18.
- 279 top-level entries: 265 `- ` bullets, 8 numbered items, and 6 `###` headings that were entries themselves (their bullets are part of the entry). The `###` group headings ("Gantt tree pane", "Gantt Excel/PDF export downloads", "Documentation vs. reality drift", "Dev environment") are not entries; their bullets are.
- 83 entries were already struck through (`~~…~~` with a Resolved, Obsolete, Moot or Cancelled note). A few more were resolved only in a note inside an unstruck entry (the `pg_trgm` index, the Drawer focus entry).
- The header's "Last whole-list code check: 2026-09-02" was out of date.
- 12 code and test comments cited entries by title or by "Ledger item N".

## Target structure

The format, severity and type definitions, area order and the rules for filing and closing are in the "How to use this file" section of `docs/ISSUES.md`. In short: one `### ISS-NNN · P? · title` heading per open issue with Type/Found/Verified, Where, Problem, fix direction and Source lines; areas in a fixed order, P1 before P2 before P3; closed issues become one line under `## Closed`. The areas match the sibling repository's list without its Pipeline area, since this product has no Pipeline module.

## Method

- Struck entries were accepted as closed with the evidence their own note cites (fixed for Resolved notes, obsolete for Obsolete, Moot, Cancelled or Stale notes). The struck "Reports screen revamp" and "velora-cron UTC crontab" entries are recorded as obsolete, because Reports (2026-08-03) and the Pipeline module (2026-09-22) were removed after they were struck.
- The 196 unstruck entries were checked against the code at `6dd7592`, by symbol rather than by the old line number. Fixed needs a commit, a CHANGELOG line naming the symptom, or an in-entry resolution note confirmed in code. Obsolete needs a deleted or rebuilt surface, or a standing decision in `CLAUDE.md`. Environment-dependent entries (flakes seen once, real-install iTop behaviour, scale triggers, accepted risks) became `watch` with their trigger.
- Where an entry matched one in the sibling repository's triage of the same day, that verdict was a hint only; this repository's code decided.
- Duplicates (same root cause, same file) were merged into the earliest entry, which lists the merged snapshot lines in its `Source:` line and takes the higher severity.
- IDs were assigned once, in file order: area order, then P1, P2, P3, then snapshot order.
