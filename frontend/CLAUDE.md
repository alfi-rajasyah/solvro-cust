# Frontend conventions (React + Vite + Tailwind v4 + TanStack Query)

- **Imports**: `@/` alias = `src/` — no deep relative imports.
- **API**: everything goes through `apiRequest<T>` in `src/lib/api.ts` (bearer from `localStorage["solvro.token"]`, base `/api`) — never call `fetch` directly from a component or hook.
- **Server state**: all hooks in `src/lib/queries.ts`; keys in `queryKeys`, admin hooks in the separate `adminQueryKeys` — don't mix namespaces. Mutations invalidate exactly what they touch, never by prefix accident. Inline-edit mutations use the optimistic pattern: `onMutate` cancel + snapshot + optimistic write, `onError` rollback, `onSettled` invalidate.
- **Auth & theme**: `AuthProvider`/`useAuth` in `src/lib/auth.tsx`; route guards are components (`src/components/AuthGuard.tsx`, `AdminGuard.tsx`, `PermissionGuard.tsx` — the generic permission gate a nav entry's `requires` pairs with; `ExecutiveGuard.tsx` wraps it). A page gated in the nav is gated in `App.tsx` too. Any 401 on an authenticated `apiRequest` signs the user out (`solvro:unauthenticated`) and clears the query cache; a 403 `forbidden` triggers a throttled `/auth/me` re-read (`solvro:forbidden`) — so never let the UI treat a non-session failure as 401. Theme only via `src/lib/theme.tsx` — never poke `documentElement.classList` directly.
- **Tailwind v4 is CSS-first**: there is no `tailwind.config.ts`/`postcss.config.js`. The theme lives in `src/index.css`'s two `@theme inline` blocks (Solvro tokens + shadcn semantic bridge). Both MUST stay `inline` — a non-inline `@theme` freezes `var(--token)` resolution at `:root` and breaks the subtree `dark` pins on Login/Sidebar. Dark mode is the `@custom-variant dark` in `index.css`. New colors/sizes go in the primary `@theme inline` block — never arbitrary hex in components.
- **Headless stack is Base-UI**: `src/components/ui/` primitives are `@base-ui/react`-backed — never reintroduce `radix-ui`.
- **Vendored code** (`ui/`, `reui/`): re-running the shadcn/ReUI CLI strips local edits — mark every hand-touched site `// SOLVRO PATCH` so re-pulls don't silently clobber. Some shadcn-registry items (e.g. `separator`) resolve their canonical `ui.shadcn.com` version through a `radix-ui` dependency and the CLI prompts interactively to install it — decline and hand-author on `@base-ui/react` instead (see `ui/separator.tsx`).
- **Popover z-index**: overrides go on the Positioner via `PopoverContent`'s `positionerClassName` — Base-UI's Positioner carries an inline transform that creates its own stacking context, so Popup-level z-index does nothing. Convention: `z-101`, exactly one above `Modal.tsx`'s `z-100` — if the modal layer ever moves, move the pickers with it.
- **Dates**: `DateField`/`DateRangeField` speak plain calendar days (`"yyyy-MM-dd"`), never ISO instants — an ISO contract caused an off-by-one-day picker walk-back east of UTC. Convert only at call-site boundaries via `src/lib/dateField.ts`; persisted `Task.startDate`/`dueDate` remain ISO instants.
- **Display dates and words**: show dates only through `src/lib/formatDate.ts` (day-first, 24-hour, host-locale-independent) — never `toLocaleDateString`/`Intl` or per-screen month lists. Domain enum display text (statuses, priorities, risk, weekly) comes from `src/lib/labels.ts` — never hand-write "To do"/"In progress" etc. in a component. Type sizes use the named roles in `index.css` (`text-meta` for 12px chips/secondary text) — no arbitrary sub-12px `text-[Npx]`.
- **Mobile**: usable down to 375px; desktop-only chrome behind `md:` (768px) — never a separate mobile component tree. Modals go edge-to-edge on phone via `Modal.tsx`; the Gantt is desktop-only with `ProjectList` as the phone fallback.
- **Icons**: app chrome uses the `material-symbols-outlined` font; `lucide-react` appears only inside vendored `ui/`/`reui/` files (ignore `components.json`'s `iconLibrary: "lucide"` for app code).
- **Navigation**: Sidebar and the ⌘K palette both render from the single `NAV_COMMANDS` catalogue in `src/lib/navCommands.ts`; top-bar titles/breadcrumbs come from `src/lib/routeMeta.ts`. A new project sub-view registers in both `App.tsx` (route) and `ProjectDetail.tsx` (tab list).
